# Phase 2 · 每日任务、学习记录与打卡

此页保留 Phase 2 的阶段记录。最新词汇实现、升级路径与验收见 [Phase 3 指南](phase3-guide.md)。

本阶段已把工作台接入真实持久化记录。未配置 Supabase 时，使用单独标注的浏览器本地模式；配置后由 PostgreSQL RPC 执行计划与写入。没有部署、创建公开仓库或购买服务。

## 新增功能

- 按每日 30/60/90 分钟生成任务，优先安排到期复习；根据最近 30 天错误率调整 Verbal/Quant 的分配，并显示薄弱题型。
- 手动完成/撤销线下学习任务，显示完成数量和百分比。重复提交同一完成状态不会增加数量。
- 记录实际学习分钟数和说明；达到时间预算后自动完成时长任务。勾选任务不会虚增学习时长、词汇掌握量或答题正确率。
- 全部任务完成后打卡；同一用户同一本地日期仅计一次。打卡后锁定任务和计划，仍可追加时长与备注。
- 学习目标修改后，可显式重排尚未打卡的今日计划。目标未增加的已完成任务保留；增加目标的任务需要重新完成。历史计划不重写。
- 今日学习备注、按月日历、按日期查询、历史任务完成情况和每条时长记录。
- 当前/最长连续打卡、累计学习天数、总分钟数、真实七天趋势、实际词汇与练习统计。没有答题记录时显示“—”，而非虚构正确率。

词汇和题目界面仍分别安排在 Phase 3/4；现在的词汇与练习任务可以记录你在应用外完成的学习。时长是用户手动申报的学习记录，没有声称经过计时器测量或自动验证。

## 立即运行

当前工作区已有依赖，在项目目录执行：

```powershell
Set-Location 'path\to\gre-pilot'
node ../../work/npm/package/bin/npm-cli.js run dev
```

安装了完整 Node.js/npm 的机器，或下载源码包后：

```powershell
npm ci
Copy-Item .env.example .env
npm run dev
```

保留已有 `.env`，不要重复复制覆盖。没有云端配置时留空两个 Supabase 变量，点击“进入本地体验”。原 Phase 1 的本地目标设置会保留，本阶段增加新的独立学习记录键。

## 手动验收

1. 打开工作台，确认自动出现今日任务，累计统计均为 0，趋势图显示空状态。尚未完成任务时不能打卡。
2. 实际完成线下学习后，勾选相应任务。试着撤销再勾选，数量不会重复增加。
3. 在“记录学习时长”填写实际分钟数并保存。达到计划预算后，“记录学习时长”任务自动勾选。
4. 填写学习备注并保存；完成所有任务后点击“完成今日打卡”。成功后显示“今日已打卡”，任务和重排按钮锁定。
5. 刷新页面：完成情况、打卡、分钟数、备注和历史仍存在；七天趋势只画保存过的时长。
6. 在日历选日期，查看当天任务、备注和时长条目；查询无记录日期应显示空状态。
7. 在第二个标签页打开同一账号/本地体验；保存记录后刷新或切回另一个标签页，数据应同步。自动刷新周期为 30 秒，切回窗口也会刷新。
8. 修改 Settings 中的时间预算，回到工作台，未打卡的计划只有点击“按最新目标重排”才调整。已打卡的计划保留。
9. 按设置的时区进入下一天后，自动生成新计划；昨天的记录仍可查询。无需修改真实系统时钟：自动化测试已模拟本地午夜。

## Supabase 升级

如果 Phase 1 迁移已经执行，只需要执行新文件：

`supabase/migrations/202611020002_daily_learning.sql`

新项目则按文件名顺序执行两份迁移。不要重复执行第一份迁移。新迁移增加 `study_days`、`study_events` 和任务字段；前端调用 `study_action` RPC。旧有学习表继续保持禁止浏览器直接写入，认证用户只被授予该受控 RPC 的执行权限。

云端日期由数据库在获得用户行锁后读取当前时间计算，客户端不能传入任意日期补签。所有修改操作携带界面显示的日期；若已经跨天，数据库返回 `DAY_CHANGED`，界面刷新后要求重新操作。重复打卡唯一约束、每用户行锁和时长请求 UUID 共同防止重复写入。

每一天保留创建时的时区与时间预算快照。修改时区会按新时区寻找当前日期，不重写历史，也不合并两个不同日期。返回已经存在的日期时，复用原计划和打卡。跨时区旅行可能跳过日期，因此连续天数按日期序列计算，而不是每隔 24 小时计算；同一日期始终只能打卡一次。

## 测试与边界

```powershell
npm run lint
npm run typecheck
npm test
npm run build
npx playwright install chromium
npm run test:e2e
```

本轮增加了本地 PGlite 测试，它运行 PostgreSQL 的 WASM 版本，并在测试中构造最小 Supabase 身份接口，然后原样执行两份迁移。它可以验证 SQL 语法、触发器、RPC 与 RLS；不覆盖 Supabase Auth 邮件、PostgREST HTTP、托管数据库配置或多数据库连接的真实并发。真正的多标签并发由浏览器本地模式 E2E 验证，托管多会话并发仍需连接云端后验证。

现有验收结果见 [phase2-verification.md](phase2-verification.md)。尚未提供 Supabase 凭据，不能将本地数据库测试表述为云端验收通过。

## 最值得学习的新增文件

| 文件 | 学习重点 |
| --- | --- |
| `src/algorithms/dates.ts` | 时区日期、日期加减、连续打卡；为什么不能简单加 24 小时 |
| `src/algorithms/planner.ts` | 时间预算分配、到期复习优先、低样本下避免误判薄弱项 |
| `src/algorithms/study.ts` | 纯状态转换：先计算，失败不改原数据，成功才提交 |
| `src/services/study.ts` | 本地与云端持久化接口；Web Locks 如何串行化跨标签页修改 |
| `src/hooks/useStudy.ts` | 加载、错误、提交与日期刷新 |
| `src/pages/Dashboard.tsx` | 用真实记录计算工作台视图 |
| `src/features/study/` | 独立表单、日历和历史组件 |
| `supabase/migrations/202611020002_daily_learning.sql` | 事务、行锁、唯一约束、受控 RPC 与 RLS |
| `src/tests/database.test.ts` | 在实际 SQL 引擎中验证隔离和 TypeScript/SQL 计划一致性 |

“幂等”表示相同提交重试多次，结果仍等同于提交一次。本项目给每条时长记录一个 UUID；网络失败后重试会复用它。不同 UUID 表示不同学习记录，即使分钟数相同也会分别累计。

## 当前限制

- 本地模式只在当前浏览器保存，不提供账号隔离，清理站点数据会丢失记录。需要 Web Locks，以及 HTTPS 或 localhost。
- 目前一次加载个人全部学习快照以支持准确累计统计；大量长期记录后，应改成服务端累计值与分页历史，避免响应越来越大。
- 时长暂不支持修改、删除或补录过去日期；备注目前可编辑今天，历史只读。误填记录的更正界面尚未实现。
- 没有历史补签，不会把手动任务当作词汇掌握或客观答题成绩。
- 仅在本轮范围内实现规则型每日计划。SM-2、学习模块自动上报和完整自适应建议仍属于后续阶段。
