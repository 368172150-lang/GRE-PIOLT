# Phase 3 · 词汇学习与间隔重复

词汇模块已接入每日计划。卡片、拼写和释义选择都保存实际学习记录；手动勾选线下任务不会伪造词汇掌握量。Phase 1/2 的目标、时长、备注和打卡继续保留。

## 本阶段功能

- 24 个原创示例词条，含 IPA、词性、英文定义、中文释义、原创双语例句、近反义词、难度、标签及内容来源。
- 今日学习队列：按到期日期排序，先复习，再补充今日计划剩余的新词。每日词汇数量读取冻结的任务目标，遵守 Phase 2 的时间预算；修改设置后，需在工作台重排未打卡的计划。
- 可翻面的词卡、四档自评、英语发音、收藏、关键词搜索、掌握状态/到期/收藏/错词筛选。
- 拼写与释义选择测验、逐词答案反馈、原错误答案和错误频次、重新练习。
- 可校验和预览的个人 CSV 导入；重复词跳过，不覆盖现有词条。导入确认只影响自己的词库。
- SM-2 变体安排下一次复习，持久化日期、间隔、难度系数、连续成功次数与遗忘次数。
- 完成当天新词/到期词数量后，自动完成对应每日任务；不会自动增加学习分钟数。
- 到期提醒显示在应用内；再次打开页面、切回窗口或每 30 秒刷新时更新，没有后台推送服务。

## 运行与验证

当前工作区已安装依赖：

```powershell
Set-Location 'path\to\gre-pilot'
node ../../work/npm/package/bin/npm-cli.js run dev
```

普通 Node.js/npm 环境或解压源码包后，在项目目录执行：

```powershell
npm ci
npm run dev
```

未配置 Supabase 时，点击“进入本地体验”，进入“词汇学习”。原 Phase 2 本地数据会原样保留；词汇进度新增在同一份学习数据中，跨标签页写入使用同一把 Web Lock。

手动验证建议：

1. 点击“开始今日学习”→回想词义→“翻转卡片”→选择“记得”。查看下一次复习日期，再刷新，确认状态保存。
2. 收藏一个词，搜索或按“已收藏”筛选，打开词义详情；试用英语发音和 Escape 关闭弹窗。
3. 把学习方式改为“拼写测试”，输入一个错误答案。反馈应显示正确拼写和释义，词库的“错词记录”应保留原错误答案。
4. 改为“释义选择”，选择答案并查看反馈。未到期词的正确额外练习不应连续推高复习间隔。
5. 点击“导入 CSV”→下载模板→选文件→检查预览→勾选内容与权限确认→导入。搜索 `lucid`；重复导入应跳过重复词。
6. 完成计划数量的新词后回到工作台，对应任务应自动勾选；学习时长应保持原值。
7. 下一本地日期再打开应用，应出现到期复习提醒。自动化测试已模拟午夜，不需要修改真实系统时间。

## Supabase 升级

已有 Phase 2 项目：先执行 `supabase/migrations/202611020003_vocabulary.sql`，再执行 `supabase/seed.sql`。

新项目：按 001、002、003 顺序执行全部迁移，再执行 seed。不要重复执行已经应用过的迁移。seed 只写本项目稳定 UUID 的原创公共词条，不创建用户进度或模拟学习活动。

第三份迁移增加 `vocabulary_reviews`（总计 16 张业务表），为词汇添加可空的 `owner_id`，并把原来的全局单词唯一约束改为公共词库/每个用户独立的唯一索引。两个账号可分别导入同一拼写，彼此看不到私人词条、进度和答题记录。

`vocab_action` RPC 在数据库中验证用户、词条访问权限、输入、日期和进度版本，再确定测验结果并更新 SM-2。没有客户端传入“是否正确”或“已掌握”的写入接口。卡片自评明确属于自报记忆情况。浏览器仍不能直接修改进度或答题表，内部 helper 不对普通用户开放。

学习请求 UUID 用于重试去重；进度版本拒绝过时标签页。一次提交里的答题、计划更新和任务自动完成在同一事务中处理。应用不会把已有本地进度自动上传或合并到 Supabase。

**本轮没有 Supabase 凭据。SQL 与 RLS 已在本地 PostgreSQL/PGlite 验证，但托管 Supabase Auth、PostgREST 和真实多连接并发仍待验证。**

## CSV 格式

下载的模板含以下列，列名必须完整，列表字段用 `|` 分隔：

```csv
word,ipa,part_of_speech,definition_en,definition_zh,example_en,example_zh,synonyms,antonyms,difficulty,tags
```

支持 UTF-8 BOM、CRLF、带逗号的双引号字段、字段内换行和 `""` 转义。每次最多 200 个词、500 KB，难度为 1–5。除 IPA 可留空、列表可为空外，内容字段必须填写。格式错误时整批不导入，并提示行号或缺失列。

导入前请核对内容与使用权限。导入是用户对个人资料的明确审核确认，不会把内容发布到公共库，也不会把未审核的 AI 内容自动加入正式共享词库。当前不提供内容编辑/覆盖或学习进度导入；同一可见拼写仅保留原词条。

## SM-2 规则与差异

算法说明见 [learning-algorithm.md](learning-algorithm.md)。本实现使用 SM-2 的记忆质量和难度系数思路，做了明确的产品简化：

- 初始 EF 为 2.5；正确回想的间隔依次为 1 天、6 天，再用上次间隔乘上次 EF 向上取整。
- EF 根据 0–5 的质量更新，保留两位小数，下限 1.3。间隔限制为 1–365 天。
- 质量小于 3 时清零连续成功次数、增加遗忘次数、次日再复习；不实现同一会话里的分钟级重学。
- 卡片按钮对应 0、3、4、5；测验正确为 4，错误为 1。
- 未到期词的正确额外练习只记历史，不推进计划；错误会重置到近期复习。重复请求只计一次。
- “已掌握”是本项目的保守状态：至少连续成功 3 次，且间隔至少 15 天。它不是官方 GRE 水平或长期记忆保证。
- 复习使用用户时区下的日期，避免把跨夏令时的一天简单当成 24 小时。

算法来源：[SuperMemo 的算法历史说明](https://www-beta.supermemo.com/en/articles/history)。项目自行实现并测试，没有复制商业题库内容。

## 内容与发音

示例释义和例句为本项目原创、AI 辅助编写；经过本轮内容检查和结构化测试，但没有冒称由独立语言专家或 ETS 审定。提供的是便于立即体验的种子内容，仍需继续扩充和人工维护。IPA 为宽式参考，不是音频文件；实际音色和口音由系统英语语音包决定。

音频使用浏览器 [SpeechSynthesis API](https://developer.mozilla.org/en-US/docs/Web/API/SpeechSynthesis/speak)。E2E 验证的是发音调用，不能证明用户设备实际有声；请在自己的设备上试听。项目不下载或再分发词典音频。

修改示例内容后运行：

```powershell
npm run content:build
npm test
```

生成器会更新 seed.sql 和下载模板，不写任何用户数据。`src/data/vocabulary.json` 每个词条都有显式固定 UUID；新增词条时分配新 UUID，不要改动已有 ID。这样插入新词或调整文件顺序时，原有学习进度不会被映射到其他单词。
